## 0. 一句话结论

1. **反向 greedy（stingy）在 6 个配置上全部严格劣于 ρ_3**，而且劣得很远，并随 n 增大继续变差
   （n=6: 1/2, 3/7, 3/8；n=7: 2/5, 1/3, 2/7）。20 个配置的数值吻合一个闭式猜想
   **K/((n−K−1)η + K)**（§3.1），它随 n 单调趋 0，即"大集合查询本身"不提供任何常数保证。

2. **组合算法（前向 greedy 与反向 greedy 按 f̃ 取较大者）在 n = 6 = 2K 的三个 η 上全部严格优于 ρ_3**：
   182/311 > 9/16、21/44 > 7/15、43/108 > 7/18（差分别为 +0.0227、+0.0106、+0.0093，远超 1e−9 阈值）。
   搜索是**穷尽**的（status = OK，符号削减经 Gate 3 与 n=6 全枚举双重验证），三个配置都做了
   **精确有理 witness 复核**（Fraction 算术下 monotone / submodular / band 逐条成立，比值分别精确等于
   182/311、21/44、43/108）。**这三格标【最需人类判断】**，见 §3.2 与 §6。
   **但同一算法在 n = 7 的三个 η 上全部严格劣于 ρ_3**（982/1885、53/131、466/1397，差 −0.042 ~ −0.062）。
   所以"超越"只出现在 n = 2K 的最小基集上，n 增大一格就消失。

3. **三个算法的值全部严格低于 1/η**。这一点很关键：台账 T8 的副产品指出，对 f̃ 穷举 K-子集的 exhaustive 算法
   在 1 ≤ η < K 时保证 1/η 且严格优于 ρ_K，所以"某个大查询算法超过 ρ_3"**本身不新奇**（exhaustive 就是）。
   本次真正的新内容是：一个**多项式查询数**的大查询算法（(b)：n=6 时 35 次查询）在 n = 2K 上落在
   (ρ_3, 1/η) 的中间；而它在 n = 7 上就掉回 ρ_3 以下。

4. 因此本任务**不支持**"任意大小查询类的最优常数高于 greedy"这一结论，也**不支持**其反面。
   诚实的说法是：在 K = 3、n ≤ 7 的范围内，被测的三个多项式查询数大查询算法里，只有组合算法
   在 n = 2K 上超过 ρ_3，且这个超越随 n 消失；**越出 K = 3、n ≤ 7 不得声称任何东西**。

## 1. 编码与对称性闸门

### 1.1 模型、变量与归一化

与 `code/worst_case_lp.py`（冻结框架，本任务只 import 不改）、`results/H_F_partial_enumeration.py`、
`results/L2_linear_candidates.py` 完全同一套：

- 变量：2^n 个 f(S) 与 2^n 个 f̃(S)（列号 S 与 N+S，N = 2^n）。
- f 单调（f(S) ≤ f(S∪e)）、submodular（d_e(S∪e′) ≤ d_e(S)）、f(∅) = 0；f̃ 任意、f̃(∅) = 0。
- f̃ 只受 Definition 1 的 single-element 误差带约束：对**所有** S 与 e ∉ S，
  d_e(S)/η_u ≤ d̃_e(S) ≤ η_o·d_e(S)，η = η_u·η_o。**f̃ 不要求单调、不要求 submodular**。
- 归一化：固定一个 K-子集 O，令 f(O) = 1，目标 min f(输出集)，再对 O 取 min。
  任一实例按 f(O\*) 归一后是 O = O\* 那支 LP 的可行点；反之 LP 可行点的真实比 ≤ 目标值（因为 OPT ≥ f(O) = 1），
  两个 min 相等。这是冻结框架的既有约定。
- 任务书写的"f(S) ≤ 1 对 |S| ≤ K"这条 cap 是**可选**的（脚本 `--cap`）：加上它 O 就是真正的最优集，
  每支 LP 的值变大，但对 O 取 min 之后相等。**Gate 5 数值验证了这一点**（4/4，差 ≤ 1.7e−16）。
  主结果用不加 cap 的版本（与冻结框架逐行一致）；§4.4 的一致性检查显示所有 argmin 解的 OPT 恰好 = 1，
  即 cap 在 argmin 处自动紧。

行构造直接复用 `H_F_partial_enumeration.model_rows` 与 `LPBuilder`，所以本脚本与 H-F / L2 的 LP 是逐行同一套模型，
差别只在"算法路径"那几行。

### 1.2 三个算法的精确定义与查询审计

**(a) 反向 greedy（stingy，NWF 1978 §4 Theorem 4.4 的预测版 [CITATION-NEEDS-VERIFICATION]）**
S ← N；重复 n−K 次：选 d ∈ argmax_{e∈S} f̃(S∖{e})（等价于预测损失 f̃(S) − f̃(S∖{e}) 最小），S ← S∖{d}；
输出剩下的 K 个元素。**tie 由对手挑。**

**(b) 组合**
T_f = 从 ∅ 起的 K 步前向 predictive greedy（每步 argmax_e d̃_e(S)，tie 对抗；与 L2 的 `greedy_rows` 同一编码）；
T_r = (a) 的输出；输出 f̃(T_f) 与 f̃(T_r) 较大者（**tie 对抗**，即相等时对手挑）。

**(c) 双向评分前向 greedy**
K 步前向 greedy，但候选评分为 score_e(S^t) = √(d̃_e(S^t)·δ̃_e)，δ̃_e = f̃(N) − f̃(N∖{e})；tie 对抗。
（两个因子都非负：d_e ≥ 0 由单调性，d̃_e ≥ d_e/η_u ≥ 0 由带；所以比较几何平均 ⟺ 比较乘积。）

查询审计（这是 P2 的要点：查询大小**超过** K）：

| 算法 | 查询集合大小 | 查询次数 (n=6) | 查询次数 (n=7) | 多项式 |
|---|---|---|---|---|
| (a) | K … n（含 f̃(N) 与全部 f̃(N∖{e})） | 18 | 26 | O(n²) |
| (b) | 1 … n | 35 | 46 | O(nK + n²) |
| (c) | K 与 n（greedy 的 ≤ K，加 f̃(N)、f̃(N∖{e})） | 22 | 26 | O(nK + n) |

三者都是**确定性、多项式查询数**，但都不落在 L1 的 𝒜_lin 内（后者要求查询大小 ≤ K）。

**与 J5 攻击的区别（必须写清）**：(a) 与 (c) 用的 f̃(N∖{e}) 正是 J5 攻击用的那类查询。J5 说的是
**在旧 hardness 族上**这些查询会泄露 O（对 e ∈ O 与 e ∉ O，G(N∖{e}) 取值不同）。本任务算的是
**任意实例上的最坏情形**。两者是不同的命题：某算法在某一族构造上表现好，不蕴含它有更好的最坏保证；
本表恰好给出反例：(a) 能穿透旧族却在最坏情形下远劣于 greedy。

### 1.3 (η_u, η_o) 的拆分：本文取 (η, 1)

三个算法的每一条决策都是两个 f̃ 值的比较（(a) 比 f̃(S∖{e})；(b) 的 greedy 比 f̃(S∪e)、最后比 f̃(T_f) 与 f̃(T_r)；
(c) 比乘积，两个因子同时按 c 缩放变成 c²，比较方向不变）。把 f̃ 换成 c·f̃（c > 0）不改变任何比较的方向与相等关系，
而 (η_u, η_o)-band 变成 (η_u/c, c·η_o)-band，乘积不变。所以最坏值只依赖乘积 η。
本文取 (η_u, η_o) = (η, 1)，使 η ∈ {1.5, 2, 2.5} 时 LP 的每个系数都是有理数，witness 的 Fraction 精确复核才有可能。
**Gate 4 数值验证了拆分不变性**（4 组 × 3 个拆分，spread ≤ 1e−16）。

### 1.4 每条"按 f̃ 比较"的决策 → 弱线性不等式

- (a) 第 t 步（状态 S，删 d）：对每个 e ∈ S、e ≠ d 写 f̃(S∖{e}) − f̃(S∖{d}) ≤ 0；
- (b) 的 greedy 第 t 步：对 e ∉ S_t、e ≠ g_t 写 f̃(S_t∪e) − f̃(S_t∪g_t) ≤ 0（公共项 f̃(S_t) 抵消）；
- (b) 的最终比较：输出 T_f 那支写 f̃(T_r) − f̃(T_f) ≤ 0，输出 T_r 那支写 f̃(T_f) − f̃(T_r) ≤ 0。

全部是**弱**不等式，等号处两支同时可行，对分支取 min 即自动实现 adversarial tie。
三个算法的规则本来就没规定 tie 时选谁（argmax / "较大者"），所以这里不存在 L2 候选 B 那种
"严格大于 vs 弱不等式"的偏差，**不需要 ε-余量研究**。

### 1.5 对称性削减与配套的 WLOG 闸门

**(a)**：算法完全等变（每步都是 argmax，没有用到元素编号顺序）。对任意置换 σ，实例 (f,f̃) ↦ (f∘σ⁻¹, f̃∘σ⁻¹)
保持模型行不变，并把删除序列 (d_1,…,d_{n−K}) 映到 (σd_1,…,σd_{n−K})、把 O 映到 σO，LP 值不变。
群在删除序列上传递，故可**固定删除序列为 (K, K+1, …, n−1)**（输出 {0,…,K−1}）；
再用该分支的稳定子群 Sym({0..K−1}) 把 O 降到轨道代表。分支数 n!/K!·C(n,K) → 8（n=6）/ 15（n=7）。
**Gate 2：固定删除序列的值 = 全部有序删除序列枚举的值**（8/8 通过，差 ≤ 3.4e−16，见 §4.2）。

**(b)**：前向 greedy 与反向 greedy 都等变，最终比较也等变。但**不能同时固定两条轨迹**。
合法的削减是：把（对手选定的）前向轨迹 relabel 成 0→1→…→K−1，**删除序列仍须跑遍全部 n!/K! 个有序序列**；
残余群是 Sym({K..n−1})（Sym({0..K−1}) 会打乱前向轨迹的顺序，不在稳定子内），用它把 (删除序列, O) 对降到轨道。
分支数 2·n!/K!·C(n,K) → 500（n=6）/ 1715（n=7）个轨道，每个轨道最多 2 支比较分支。
**Gate 3：轨道代表的值 = 全 (删除序列, O) 枚举的值**（12/12 通过，其中包含 **K=3, n=6 的三个 η**，
即本报告 §0 第 2 条那三格是用 4680 次 LP 的全枚举独立复核过的，见 §4.3）。

## 3. 逐算法讨论

### 3.1 (a) 反向 greedy：一个闭式猜想，以及 η = 1 的行为

20 个配置（K ∈ {2,3,4}，n ∈ {5,6,7,8}，η ∈ {1, 1.25, 1.5, 2, 2.5}）的精确值全部吻合

> **[CONJECTURE]**  反向 greedy 的最坏比 = **K / ((n − K − 1)·η + K)**

（吻合表见 JSON 的 `closed_form_A` 与 `results` 两节；10 个额外配置逐点 match=True。）
两个读法：

- **η = 1（完美预测，此时 band 强制 f̃ = f，就是经典 stingy 算法）**：公式给 K/(n−1)，
  数值确认 n=6 → 3/5、n=7 → 1/2、n=8 → 3/7（K=3），K=2 时 n=5 → 1/2、n=6 → 2/5。
  即**经典反向 greedy 的最坏比随 n 像 1/n 衰减，没有常数保证**，与 greedy 的 1 − (1−1/K)^K = 19/27 相去甚远。
  这与教科书里"stingy/reverse greedy 对基数约束下的 monotone submodular 最大化不是常数近似"的印象一致，
  但 **NWF 1978 §4 Theorem 4.4 的原文陈述我没有核对，标 [CITATION-NEEDS-VERIFICATION]**：
  引用时只能说"本脚本算出的 η=1 值是 K/(n−1)"，不能说"复现了 NWF 4.4"。
- **η > 1**：分母里 η 只乘 (n−K−1)，即误差只放大"多余元素"那一段的损害。η → ∞ 时值 → 0。

结构上的原因（**[HAND-PROOF-UNREVIEWED]**，仅作解释不作证据）：反向 greedy 在前几步面对的是很大的集合，
此时每个元素的边际都被 submodularity 压得很小、彼此接近，预测误差足以把 O 里的元素排到"损失最小"的位置删掉；
删掉之后再也没有机会补回来。n 越大，这种"早期无信息删除"的步数越多。

### 3.2 (b) 组合：n = 2K 超过 ρ_3，n = 7 掉回去【最需人类判断】

三个 n = 6 的值分别是 182/311、21/44、43/108，比 ρ_3 高 +0.0227 / +0.0106 / +0.0093。
**已按用户规程逐字执行**：

1. 搜索穷尽（status = OK，全部 980 支分支都解了 LP，没有剪枝、没有超时）；
2. 用 n=6 的**全枚举**（4680 支，不使用任何对称性削减）独立复核，三个 η 的值一字不差（Gate 3）；
3. **精确有理 witness 复核**：把 argmin 分支的 LP 最优解重建成显式 (f, f̃)，`limit_denominator(1e5)` 有理化后
   用 Fraction 算术**逐点**验 f(∅)=0、单调、submodular、band，三个配置全部 exact_ok = True；
   在该有理实例上重跑算法（所有 tie-consistent 执行，对手取 min）得到的比值精确等于
   **182/311、21/44、43/108**，与 LP 值一致。
4. 未自行解释掉：下面的讨论是观察，不是"把它解释没"。

argmin 分支（η=1.5, 2）：O = {2,3,4}，前向轨迹 0→1→2（WLOG 固定），删除序列 2→3→0，T_r = {1,4,5}，
最终比较判给 **T_r**（即反向 greedy 的输出被选中）。η=2.5 是 O = {1,2,3}、删除序列 1→2→3、T_r = {0,4,5}。
**共同点：最坏情形下胜出的总是反向 greedy 的输出。** 直觉：若对手想让前向 greedy 的坏输出胜出，
就必须让 f̃(T_f) ≥ f̃(T_r)；而 f̃ 沿链求和满足 f̃(S) ≥ f(S)/η_u，这条不等式把 T_f 的真实值抬起来，
对手为了同时压住两条路径要付出代价，代价就是 +0.009 ~ +0.023。

**为什么这不足以推翻 hardness 方向**（三条，都必须写进结论）：

- n = 7 立刻掉到 ρ_3 以下（−0.042 ~ −0.062），而 hardness 需要的是 n → ∞ 的族。
  一个只在 n = 2K 成立的优势，正好是 H-F 的先例：PE_1 在 n = 2K 严格优于 ρ_3，n = 7 就不再优于。
  **n = 2K 时基集只有 6 个元素，"隐藏 O"的空间本来就不够**，这是小基集现象的常见成因。
- 三个值全部**低于 1/η**，而 exhaustive（对 f̃ 穷举 K-子集，查询大小 K，查询数 C(n,K)）在 1 ≤ η < K 时
  保证 1/η（台账 T8 副产品）。所以 (b) 并没有碰到"大查询能做到多好"的天花板，只是在 ρ_3 与 1/η 之间。
- 没有闭式。182/311 这种分母说明最优顶点很不平凡，无法外推到一般 (K, n)。

**留给人类判断的问题**：K = 3、n = 2K 上 (ρ_3, 1/η) 之间的这个多项式查询数算法，是小基集数值巧合，
还是 n = 2K 这一类构造的真实结构？要回答它需要 n = 8, 9（K = 3）或 K = 4, n = 8 的同类计算，见 §6。

### 3.3 (c) 双向评分：评分在 f 顶端饱和时坍缩

见 §5 的完整处理。结论行是：字面版的最坏比 ≤ 算法 (a) 的值，因而**严格劣于 ρ_3**；
原因不是"几何平均误导"，而是**评分整体坍缩**：在 (a) 的 argmin 实例上 f 在顶端饱和（f(N∖{e}) = f(N) 对所有 e），
于是 δ̃_e ≡ 0、所有候选的 score ≡ 0、全部并列，adversarial tie 把输出交给对手，对手直接挑最差的 K-子集。

## 5. 算法 (c) 的处理：为什么不能精确 LP 化，以及所得的界

### 5.1 如实说明：几何平均比较是二次约束，不可精确 LP 化

算法 (c) 的每一步要判 score_e ≥ score_{e′}，即 d̃_e·δ̃_e ≥ d̃_{e′}·δ̃_{e′}。
d̃ 与 δ̃ 都是 LP 变量的线性函数，所以这是一条**双线性（二次）**约束，不是线性不等式。
(c1) 取对数把乘积变成和也没用：log 是非线性的，log d̃ 不是 LP 变量的线性函数，可行域仍非多面体。
**所以本任务不为 (c) 报告精确值，(c) 的精确最坏比标 [FAILED]。**

选定的处理：**(c3)（构造性搜索）为主**，外加一个便宜的"充分条件受限 LP"来制造更多候选实例；
**(c2)（McCormick 松弛给上下界）没做**，理由见 §6 第 2 条（时间预算，且它给的是**下界**方向，
而本任务需要的结论方向是上界）。

### 5.2 (c3)：在已知最坏实例上精确模拟

实例库（每个实例都先在全格点上验 monotone / submodular / band，band 允许 (η,1)、(1,η)、(√η,√η) 三种
同积拆分中任一成立；不通过的实例只记录、不计入界）：

- `greedy_LP_argmin_n{6,7}`：冻结框架 `worst_case_lp.worst_case` 给出的 predictive greedy 最坏实例；
- `argmin_a_n{6,7}`、`argmin_b_n{6,7}`：本任务 (a)、(b) 的 argmin 实例（§4.7 重建出来的那些）；
- `n2_instance_j{0,1,2}`、`uk_instance`：H_F / N2 的已知最坏族（只在 n = 2K = 6 有定义）。

模拟用 **Fraction 算术**（`limit_denominator` 后逐点精确验模型，再精确比较乘积；tie 用精确相等判定，
不走浮点；浮点会把 argmax 舍没，这是本次实现里改掉的一个真实 bug）。对手在所有 tie-consistent 执行里取 min。

**结果（每个数都是 (c) 最坏比的上界）**：

| n | η | (c) 上界 | 取到上界的实例 | 与 ρ_3 比 | 该实例上的 tie 分支数 |
|---|---|---|---|---|---|
| 6 | 1.5 | 1/2 | `argmin_a_n6` | < 0.5625 | 20（= 全部 K-子集） |
| 6 | 2 | 3/7 | `argmin_a_n6` | < 0.466667 | 20 |
| 6 | 2.5 | 3/8 | `argmin_a_n6` | < 0.388889 | 20 |
| 7 | 1.5 | 2/5 | `argmin_a_n7` | < 0.5625 | 35（= 全部 K-子集） |
| 7 | 2 | 1/3 | `argmin_a_n7` | < 0.466667 | 35 |
| 7 | 2.5 | 2/7 | `argmin_a_n7` | < 0.388889 | 35 |

**结论**：worst(c) ≤ 上界 < ρ_3，所以 **(c) 在全部 6 个配置上严格劣于 ρ_3**（这是一个确定的结论，
因为需要的方向恰好是上界方向）。但**它不是 (c) 的精确值**，真值只可能更低。

**机制（必须说清，否则这个上界会被误读）**：取到上界的实例正是算法 (a) 的最坏实例，
在那里 f 在顶端饱和：f(N∖{e}) = f(N) 对每个 e 成立，于是 δ̃_e ≡ 0，所有候选的 score ≡ 0，
K 步全部并列，adversarial tie 直接把输出交给对手（tie 分支数 = C(n,K)，即全部 K-子集都是合法输出），
对手挑 f 最小的 K-子集。所以这个上界反映的是"评分坍缩 + 对抗 tie"，不是"几何平均把算法带偏"。
把 f̃(N∖{e}) 这一维加进评分**至少在最坏情形下有害**：它能把一个本来有信息的 d̃ 乘成 0。

### 5.3 兜底变体 c′：score tie 时改用 d̃ 排序（无结论）

为了把 §5.2 的坍缩因素分离出来，额外模拟了 c′：score 并列时先按 d̃_e(S^t) 取大者，仍不分胜负才交给对手。
（c′ 在评分非退化时与 c 逐字相同。）同一实例库 + 受限 LP 实例上的上界：

| n | η | c′ 上界 | 取到者 | ρ_3 | 结论 |
|---|---|---|---|---|---|
| 6 | 1.5 | 4/7 ≈ 0.571429 | 受限 LP 实例 | 0.5625 | 上界高于 ρ_3 → **无结论** |
| 6 | 2 | 7/15 = 0.466667 | `n2_instance_j1` | 0.466667 | 上界 = ρ_3 → **不严格优于**（≤ ρ_3） |
| 6 | 2.5 | 13/33 ≈ 0.393939 | 受限 LP 实例 | 0.388889 | 上界高于 ρ_3 → **无结论** |
| 7 | 1.5 | 9/16 = 0.5625 | 受限 LP 实例 | 0.5625 | 上界 = ρ_3 → **不严格优于** |
| 7 | 2 | 7/15 | 受限 LP 实例 | 0.466667 | 上界 = ρ_3 → **不严格优于** |
| 7 | 2.5 | 7/18 | 受限 LP 实例 | 0.388889 | 上界 = ρ_3 → **不严格优于** |

即：加了兜底之后，(c′) 在 4/6 个配置上可以判定"**不严格优于 ρ_3**"，另外 2 格（n=6, η ∈ {1.5, 2.5}）
**只有高于 ρ_3 的上界，什么也判定不了**：上界高于 ρ_3 既不能说明优于也不能说明劣于。标 [FAILED]（未完成）。

### 5.4 "充分条件受限 LP"（制造实例的工具，不是精确值）

受限 LP 的做法：把 (c) 的轨迹决策换成一条**充分**的线性条件：被选中的元素在**两个因子上同时**占优，
d̃_t(S_t) ≥ d̃_e(S_t) 且 δ̃_t ≥ δ̃_e。两个因子非负，故乘积比较自动成立，因此该 LP 的**每个可行点都是
(c) 真的会按此轨迹执行的实例**，其最优值是 (c) 最坏比的合法上界（但因为条件是充分不必要的，界会偏松）。
加 cap（f(S) ≤ 1 对 |S| ≤ K）后对 O 取 min 的值：

| n | η | 受限 LP 值 | ρ_3 |
|---|---|---|---|
| 6 | 1.5 | 4/7 ≈ 0.571429 | 0.5625 |
| 6 | 2 | 7/15 ≈ 0.466667 | 0.466667 |
| 6 | 2.5 | 13/33 ≈ 0.393939 | 0.388889 |
| 7 | 1.5 | 9/16 = 0.5625 | 0.5625 |
| 7 | 2 | 7/15 | 0.466667 |
| 7 | 2.5 | 7/18 | 0.388889 |

读法：**在"评分两维同时占优"的那一族实例上，(c) 的表现与 greedy 基本一样**（n=7 三格精确等于 ρ_3）。
它不比 §5.2 的界更紧，所以对 (c) 的最终结论没有贡献；列出来是因为它同时是 §5.3 的界的来源。

## 6. 卡点

1. **(c) 的精确值拿不到**（二次约束，§5.1）。交出的是上界；字面版因此仍能判定"严格劣于 ρ_3"，
   但兜底变体 c′ 有 2 格无结论。[FAILED]
2. **(c2) McCormick 松弛没做**。时间预算用在了 (a)(b) 的穷尽枚举与 (b) 超越结论的三重复核上。
   补充说明：McCormick 给的是**松弛**（可行域变大）→ 目标 min 变小 → 得到的是**下界**；
   要用它判定"(c) 是否超过 ρ_3"需要的恰好是这个方向（下界 > ρ_3 才算超越），所以它仍然值得做，
   只是本次没做。需要的前置条件是 cap（否则 d̃、δ̃ 没有上界，McCormick 包络无从写）；cap 已经实现并经 Gate 5 验证。
3. **n ≥ 8 没跑**。(b) 在 n=8 的分支数是 8!/3!·C(8,3) = 6720·56 = 376320 对，即使按 Sym({3..7}) 的 120 阶群

   n=9 完全不可行。**所以 §3.2 的"n 增大就消失"只有 n=6 → n=7 一个数据点，不能外推。**
4. **Gate 7（ipm 复核）只在 n=6 跑了**，n=7 的 12 个值没有第二个求解器的旁证（它们的结论是"劣于 ρ_3"，
   方向上不依赖小余量，风险较低）。
5. **NWF 1978 §4 Theorem 4.4 的原文未核对**，只能说"本脚本在 η=1 算出 K/(n−1)"，
   不能说"复现了 NWF 4.4"。[CITATION-NEEDS-VERIFICATION]
6. **(b) 的超越没有闭式解释**（§3.2）。182/311 的分母说明顶点结构复杂。
